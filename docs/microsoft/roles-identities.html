Roles and identities

Three questions decide who can do what in Foundry: who manages the infrastructure, who builds in a project, and how an agent gets access to the services it uses.

Checked 31 Oct 2026

Who manages, who builds, how the agent gets access

Managing the Foundry resource and building inside a project are separate permissions. The agent is a third party in the picture: it has its own identity, and it can reach only what that identity has been allowed to reach.

The built-in roles

RoleManage resource and projectsBuild in a projectIn short
Foundry UserRead onlyYesThe least-privilege role for building and testing.
Foundry Project ManagerProjectsYesBuilds, manages projects, publishes agents; can grant only Foundry User.
Foundry Account OwnerYesNoCreates the resource, projects and deployments.
Foundry OwnerYesYesBoth; Microsoft calls it highly privileged.
Foundry Agent ConsumerNoNoCan only call published agents.
Azure Owner, ContributorYesNoNo Foundry data actions, so add a Foundry role to build.

The Foundry roles were recently renamed from the "Azure AI" names (Azure AI User became Foundry User, for example); older pages may still use the old names. When you create a resource in the Azure portal or Foundry portal, or a project in the Foundry portal, and you're allowed to assign roles, Microsoft says you're given Foundry User automatically. Creating them with the CLI or an SDK doesn't. If building is blocked, see the Episode 1 troubleshooting.

The identities Foundry uses

Resource

Resource managed identity

An identity for the Foundry resource itself, used when the resource needs to reach other Azure services, such as reading from a storage account.

Project

Project managed identity

Each project has one. It's used to reach backing storage, search and other resources, and by tool connections set to use it. Creating the project in the Foundry portal gives it Foundry User when the creator can assign roles.

Agent

Agent identity

Each new agent gets its own Microsoft Entra identity, with Foundry holding the credential so there's no secret to manage. It starts with no permissions; you grant it roles on the resources it should use.

Tools

Connections

A tool's authentication is set on its connection, never in the agent's code: no auth, an API key that Foundry stores, the project's or agent's identity, OAuth passthrough, or the user's own Entra token.
