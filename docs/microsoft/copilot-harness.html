The Microsoft Copilot harness

Microsoft's Copilot harness, part of Foundry Agent Service, is a managed harness. It runs the agent loop and the sandbox for you, and takes on part of the other layers. You still supply what makes the agent yours.

Checked 31 Oct 2026Public preview

You configure, Microsoft operates

This is the same picture as harness engineering, coloured by who looks after each part when you use the Copilot harness.

The parts in more detail

The harness is an optional runtime for a prompt agent: the agent stays a prompt agent, and you choose the harness when you create it. From then on Foundry runs the loop: it plans each step, calls tools, runs code in a sandbox and hands bounded work to subagents.

Three ways to build an agent in Foundry

The harness is the middle option. Each level gives you more control and more to own; Microsoft's advice is to pick the one that matches what you need.

Preview notes

It's a preview. You choose the harness when you create an agent and can't switch it later yet. To run, the agent needs a deployed model that supports reasoning and tool calling. Foundry Memory isn't available to harness agents yet; conversation history and files in the agent's workspace are. It's offered in a limited set of Azure regions, and billing for the harness runtime starts on 1 Dec 2026, with model use billed separately. Check Microsoft's pages before you build.
