Harness engineering: build the agent around the model

A model on its own predicts text. To get useful work done it needs a loop to act in, and a system around that loop: instructions, context, tools, a place to run code, controls and feedback. That surrounding system is the harness. Designing it is harness engineering.

Model, agent, engineered system

Read the diagram from the centre out. A model turns what it's given into a response. In an agent, the model picks the next action toward a goal, a tool carries it out, and the result informs the next choice, until the goal is met or a limit is reached. Around that loop we draw six layers. They're our teaching framework for what makes the system dependable; other writers group them differently.

One task, six layers

Take one request: "Research a question on the web and give me a one-page report with a chart." Here is what each layer does for it, and what goes wrong without it.

LayerFor this taskWithout it
Instructions"You're a research assistant. Cite every source. One page, plain English."The agent guesses the audience and the format.
ContextThe question, what it has found so far, and a summary once the history gets long.It repeats searches or loses earlier findings.
ToolsWeb search to find sources; a file tool to save the report.It can only answer from what the model already knows.
ExecutionAn isolated sandbox where it runs Python to draw the chart and writes the file.It can describe a chart but not make one.
ControlsOnly approved tools, a step limit, and a person's approval before anything is sent.A runaway loop, or an action nobody agreed to.
FeedbackCheck that the sources support the conclusions, the chart matches the data and the format is right; keep a trace of each step.Nobody knows whether it worked, or why it failed.

Where skills fit

A skill is a reusable procedure the agent can pick up when a task calls for it: written steps, plus any scripts and files they need. For the report, the instructions say what a good report must achieve. A skill holds the procedure for researching, checking and assembling one. The tools do the searching, calculating and saving. Skills sit between the instructions and context layers: they're loaded into the agent's context only when needed.

Where the term comes from

OpenAI used "harness engineering" in February 2026 for its team's work building the environment, tools and feedback loops that let Codex agents ship a product. Its summary of the split: "Humans steer. Agents execute."

Thoughtworks' Birgitta Böckeler describes a harness as the tooling and practices that keep agents in check. In a later article she splits it into guides, which steer the agent before it acts, and sensors, which help it correct itself afterwards.

Anthropic describes the harness as the loop that calls the model and routes its tool calls, kept separate from the sandbox where code runs and from the log of the session.

The common thread: the model is one part. Most of the engineering is in what surrounds it.
