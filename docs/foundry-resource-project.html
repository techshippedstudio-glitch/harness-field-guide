Resource and project in Microsoft Foundry

Every Foundry setup starts with two things: a Foundry resource, and a project inside it. Here's what lives where, why the first project is special, who can do what, and how cleanup works.

Checked 31 Oct 2026New Foundry portal

What lives where

The resource holds the things every project shares: model deployments, connections to other services, and network and security settings. A project is where you actually build: agents, files, evaluations, datasets and indexes. The first project on a resource is its default project. When we created our resource in the Azure portal, the form asked for a default project name and created both in one deployment.

Who can do what

Managing Azure resources and building inside a project are separate permissions. Being the subscription Owner lets you create the resource, but building agents needs a Foundry role.

RoleManage resource, projects, deploymentsBuild in a project (agents, evaluations, files)
Foundry UserRead onlyYes. The least-privilege role for builders.
Foundry Account OwnerYesNo
Foundry OwnerYesYes. Microsoft calls it highly privileged.
Azure Owner (subscription)YesNo. No data actions, so add a Foundry role.

The Foundry roles were recently renamed from the "Azure AI" names (for example Azure AI User became Foundry User); older pages may still use the old names. Foundry Project Manager is left out because Microsoft's page is inconsistent about what it can create.

Microsoft's docs

When the role is added for you

Microsoft says that if you create the resource in the Azure portal or Foundry portal and you're allowed to assign roles, you get Foundry User automatically. Creating it with the CLI or an SDK doesn't assign roles.

Microsoft Learn, RBAC for Foundry · checked 31 Oct 2026
We saw this

Check it anyway

In our subscription the portal said it would grant Foundry User, but Access control showed only our inherited Owner role. Build > Agents said "You don't have permission to build agents in this project" and offered Assign me the Foundry User role. One click fixed it.

Observed in our project, 31 Oct 2026

Two cleanup rules

Deleting a project and deleting the resource behave differently. Know which one you're doing.

Rule 1 · Project

A deleted project can't be recovered

Microsoft's page is plain about it: a deleted project is gone, along with the work inside it. There's no recovery window like the resource has.

Microsoft Learn, Create a project · checked 31 Oct 2026
Rule 2 · Resource

A deleted resource holds its name for 48 hours

Microsoft Learn describes a 48-hour window to recover or purge a deleted resource under "Manage deleted resources". Until it's purged, the name can't be reused. If you deleted the resource group too, you recreate it before recovering. The portal's delete dialog we saw warns the resource "will be permanently deleted", so don't plan on getting it back.

Microsoft Learn, Recover or purge deleted resources · observed dialog 31 Oct 2026

Following an older tutorial?

Before New Foundry, projects were built on a Foundry hub, now called a hub-based project. Those still exist and appear only in the classic portal, behind the "New Foundry" switch. Microsoft says its new investments are focused on Foundry projects in the new portal, like the ones on this page. If a tutorial's screens don't match yours, check which project type it uses.
