Microsoft Foundry from zero

Before you start

  • An Azure subscription. We use a personal one.
  • Permission to create resources and assign roles in it. In our personal subscription we're the Owner; in a company tenant you may need an administrator's help.
  • A region for Episode 2. The Copilot harness preview runs in a limited set of regions. We use Canada Central; check Microsoft's current list before you pick.

Read first, or watch the first half of the video: harness engineering, the Copilot harness, Foundry, resources and projects, roles and identities.

Walkthrough

  1. Start the create form. In the Azure portal, search for Microsoft Foundry and choose Create a Foundry resource.
  2. Fill in Basics. Pick your subscription and a resource group (ours: rg-techshipped-foundry). Give the resource a globally unique name (ours: techshipped-foundry-01). Choose the region; check it, because the form fills one in for you. Name the default project (ours: techshipped-agents).
  3. Look through the other tabs. Storage, Inbound and Outbound networking, Identity, Encryption and Tags. We kept the defaults; the Identity tab says the portal will give your user the Foundry User role.
  4. Create it. Choose Review + create, then Create. Under Deployment details you'll see two items: the resource and its project.
  5. Check the resource. Open it and look at Keys and Endpoint (the resource endpoint; keep keys private), Projects (your default project is listed) and Access control (IAM).
  6. Open the Foundry portal. Go to ai.azure.com, turn on New Foundry and choose your project. Home shows the project endpoint, ending in /api/projects/<project>; that's the one agent code uses. Look at Discover (the model catalog), Build and Manage.
  7. Confirm you can build. Open Build › Agents. You should see "Create your first agent". If you see a permission message instead, see troubleshooting below. To run an agent you'll also need a deployed model that supports reasoning and tool calling; Episode 2 starts there.

Troubleshooting

"You don't have permission to build agents in this project"

Your account doesn't have a role that can build in the project (normally Foundry User). If you're allowed to assign roles, choose Assign me the Foundry User role on that screen, wait a few minutes and refresh. Otherwise ask an administrator. We met this on 31 Oct 2026 even though we created the resource as subscription Owner.

Quota shows 0 for a model

Under Manage › Quota, our new subscription showed no quota for the model we looked at. You need quota before you can deploy that model; use Request quota. We'll deal with this in Episode 2.

The screens don't match a tutorial

Older tutorials may use hub-based projects in the classic portal. Check which project type the tutorial uses, and use the New Foundry switch to move between the two portals.

Cleaning up

Deleting a project and deleting the resource behave differently. Read the two cleanup rules before you delete anything. We're keeping ours for Episode 2.
