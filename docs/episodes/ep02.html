Microsoft Foundry Copilot Harness: Build Your First Useful Agent

A small agent that does a real job: it checks claims against the Microsoft Learn pages they cite and returns an evidence-backed report. We build it in the Foundry portal, follow its agent loop in Traces, check its result ourselves, then build the same agent in Python.

What you'll learn

Concepts
  • What the Copilot harness runs for you, and the four things you still choose
  • Instructions are the job, a skill is the method, tools are the actions
  • Why the agent's own identity needs a role before it can return a file
  • How to read the agent loop in Traces
Hands-on

Before you start

  • A Foundry project in a Copilot harness region. The preview runs in a limited set of regions; check Microsoft's current list. Episode 1 created ours in Canada Central.
  • A deployed model that supports reasoning and tool calling, with enough quota. We use gpt-5.4-mini. Bring-your-own-model isn't supported by the harness.
  • The Foundry User role on the project for your own account (Episode 1 shows how to check it).
  • For the Python part: Python 3.11 or later and the Azure CLI. The sample was tested with azure-ai-projects 2.10.0.
What we ran into with quota. On 1 Nov 2026 our subscription had no usable quota for a harness-capable model in Canada Central, so the project we created in Episode 1 couldn't run this agent. We created a second Foundry resource and default project in Central US (also a harness region) and deployed gpt-5.4-mini there as Data Zone Standard at 100K tokens per minute. In a dry run, a 50K tokens-per-minute deployment of another model returned "Model deployment rate limit exceeded" for every harness request; a one-line question used about 11,000 tokens, because the harness sends its own context. Microsoft's harness quickstart uses 100K. Your quota depends on your subscription, so check Manage › Quota before you pick a region.

Walkthrough: build it in the Foundry portal

  1. Create the agent with the harness. In the Foundry portal (New Foundry on), open your project, then Build › Agents › New agent › Build an agent. Name it (ours: fact-checker), keep interaction mode Text, and tick Use the Microsoft Copilot harness. Tick it now: during the preview you choose the harness when you create the agent, and you can't add it to an existing agent later. Choose Create agent and open playground.
  2. Pick the model. In the playground, select your model deployment.
  3. Write the instructions: the job. Ours are in instructions.md: you're a fact-checking assistant; follow the fact-check skill for the method and the report format; base every verdict only on the cited page; write report.md and return it as a downloadable file; then reply with one line per claim. They don't contain the steps; those go in the skill.
  4. Create the skill: the method. Under Tools, choose Add › Add skills and create a new one. Name fact-check; description "Check each claim against its cited source and write an evidence-backed report."; paste the instruction body from SKILL.md (everything after the front matter). Skills are versioned Foundry resources, and each agent version keeps the exact skill version it was saved with.
  5. Choose the tools: the actions. Open Harness tools. File system read, File system write, Web, Shell and Subagents are all on by default. Our agent needs Web and the two file tools, so we untick Shell and Subagents, then Done. Microsoft calls Shell the broadest harness tool; switch off what an agent doesn't need.
  6. Save. Choose Save and start new chat. The agent gets a new version with everything you set.
  7. Find the agent identity. On the agent's Details tab, Identity and access shows its Entra agent identity. Note its object ID; you need it in the next step.
  8. Give that identity Foundry User on the project. In the Azure portal, open the project (not the resource), then Access control (IAM) › Add › Add role assignment. Choose Foundry User; under Members choose Select members and search for the object ID; select it, then Review + assign. Assign it to the agent identity, not to the project's managed identity. Allow up to five minutes before you test. (Why: the agent writes report.md in the conversation's workspace, and the harness uploads it to Foundry Files using the agent's own identity, which starts without resource permissions.)
  9. Run it. Paste the four claims from claims.md into the chat and send. Claim 4 is wrong on purpose. Our run replied in about 13 seconds with four verdict lines (three Supported, one Contradicted) and a report.md chip.
  10. Follow the agent loop. The reply's footer lists what was used; open Traces. Our run recorded: a model call, the skill load, a model call, two web_fetch calls, a model call, apply_patch (writing the report in the workspace), a model call, the upload to Foundry Files, and a final model call. The Graph view shows the same run as a tree.
  11. Check the result yourself. Download the report and open it: each claim, its verdict, a quote of at most 15 words, and the source page with its last-updated date. Then open one cited page and search for the quoted sentence. Ours, "Foundry Memory stores and memory tools aren't available", is on the limits page word for word. Do this before you trust a verdict.
  12. Look at the definition. The playground's YAML tab shows what you built: a prompt agent, harness: type: microsoft_copilot_preview, the model, the instructions, the skill reference and the tools block with shell and subagents disabled.

The same agent in Python

The sample in code/ep02-first-useful-agent builds the same definition with the Azure AI Projects SDK: create_agent.py publishes the skill as a new version and adds a new version of the agent (a new version keeps the harness the agent was created with); run_agent.py opens a conversation (every harness request needs one), sends the claims, waits, and downloads report.md. It signs in with your Azure CLI login; there are no keys in the code.

pip install -r requirements-lock.txt
cp .env.example .env        # your project endpoint and model deployment name
az login
python smoke_test.py        # offline check
python create_agent.py      # skill + agent versions
./assign_agent_role.sh      # Windows: .\assign_agent_role.ps1 (only if the agent is new)
python run_agent.py         # conversation, run, download

Our recorded run on 1 Nov 2026 completed in 18 seconds with the same four verdicts, and the portal then showed the code-created version as active, with its trace labelled with that version. The README has the full setup.

The repository's skill is refined. The video shows the first skill version, with three verdicts (Supported, Contradicted, Not found); that state is tagged foundry-ep02-recorded. The skill in main splits "Not found" into Insufficient evidence (the page doesn't address the claim) and Source unavailable (the page couldn't be fetched), allows "No evidence retrieved", and makes each source a link. run_agent.py also now stops with an error if no report comes back.

Troubleshooting

The agent replies, but no file comes back

The upload to Foundry Files uses the agent identity. Check that the agent identity (not your account, not the project's managed identity) has Foundry User on the project, and wait up to five minutes after assigning it. In Python, run_agent.py stops with "The agent didn't return a downloadable file".

The report chip doesn't save a file

In our portal run, clicking the report.md chip didn't leave a file in our downloads folder. The file was in the project under Data › Datasets (named after its Foundry file ID), where Download worked.

"Model deployment rate limit exceeded"

Every harness request carries the harness's own context, about 11,000 tokens before your prompt in our test. A deployment with a low tokens-per-minute limit can reject every request. Raise the deployment's limit (we use 100K) or request more quota.

No harness option on an existing agent

During the preview the harness is chosen when an agent is created and stays fixed. Create a new agent with the box ticked; new versions keep the harness.

The agent acts like a coding assistant

Without instructions, a harness agent described itself to us as a coding helper. The instructions set the job; write them before you test.

Cleaning up

Agents, skill versions and model deployments stay in the project until you delete them; check Cost Management in the Azure portal for what your project is costing. Read the cleanup rules before you delete a project or resource. We're keeping ours for the next episode.
